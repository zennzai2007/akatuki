# YUマーケット

山口大学の学内で、不要になった物を**無償でゆずりあう**ためのサイトです。
お金のやり取りは一切なく、価格・決済の機能はありません。

公開先: <https://zennzai2007.github.io/akatuki/>

画面はバニラの HTML/CSS/JS（ハッシュルーター）で作り、ログインとデータ保存に Supabase を使っています。

## 画面

| 画面 | ハッシュ | 内容 |
| --- | --- | --- |
| ログイン | `#/login` | メールアドレス・パスワード、新規登録への導線 |
| 新規登録 | `#/signup` | 山口大学のメールアドレス・パスワード（8文字以上）・確認入力。確認メールのリンクを開いて登録完了 |
| ホーム | `#/home` | 検索窓、カテゴリー絞り込み、新着商品（自分の出品は出ない） |
| 検索 | `#/search` | カテゴリー／受取場所／取引可能期間／キャンパスで絞り込み、一覧表示（自分の出品は出ない） |
| 検索結果 | `#/results` | キーワード検索の結果をリスト表示。条件はチップで表示し「×」で解除 |
| 商品詳細 | `#/item/:id` | 写真・商品説明・各項目・出品者。自分の出品や受付終了の出品には申し込めない |
| 申込確認 | `#/apply/:id` | 受取可能日・受取希望場所・メッセージ・利用規約への同意 |
| 出品情報の入力 | `#/sell` | 写真の追加（長辺1024pxに縮小、iPhone の HEIC にも対応）、商品名、各項目、商品の説明 |
| 取引 | `#/transactions` | 届いた申込（承認・断る）・申し込み中・取引中・取引履歴を1画面にまとめて表示。履歴から出品者を評価する |
| メッセージ | `#/chat/:id` | 取引中の当事者2人だけのやりとり。受け渡しが完了すると消える |

商品ページとメッセージ画面には「通報する」があり、理由と補足を送れます（出品の通報＝その出品者への通報、メッセージ画面＝取引相手への通報）。自分の出品は通報できません。
| 出品中の商品 | `#/listings` | 自分の出品と状態（出品中／取引中／譲渡済み／取消済み）。受付中の出品の取り消し |
| プロフィール | `#/mypage` | 名前・学部・キャンパス・プロフィール画像の編集、取引・出品中の商品へのメニュー、ログアウト |
| 利用規約 | `#/terms` | 運営・無償譲渡・トラブル・メールアドレスの扱い。申込確認と新規登録から開く。ログイン前でも読める |

下のタブは ホーム / 検索 / 出品 / マイページ の4つです。取引まわりはマイページの「取引」にまとめています。

## 取引の流れ

1. 出品者が写真付きで出品する
2. ほかの学生が商品詳細から申し込む（申込中）
3. 出品者が「取引」画面の「届いた申込」で承認する（取引中）
   - 同じ出品へのほかの申込は自動で取消になり、出品は検索に出なくなる
   - 承認から受け渡し完了までの間、当事者2人だけの「メッセージ」で日時・場所を相談できる
4. 受け渡しが済んだら、出品者が「受け渡し完了」を押す（取引完了）
   - 両者の取引履歴に載り、メッセージは削除される
5. 受け取った人は、取引履歴から出品者を「よかった / 困った」で評価できる（1取引につき1回）
   - 合計は商品詳細の「出品者の評価」と、自分のマイページに「よかった 5 / 6件」のように出る

承認・受け渡し完了・取消は、データベースの関数（RPC）でだけ行えます。画面から申込の状態を直接書き換えることはできません。

## 動かし方

### Supabase の準備（最初に1回）

1. Supabase でプロジェクトを作る
2. SQL Editor で `supabase/schema.sql` を実行する
3. Authentication → URL Configuration で次を設定する
   - Site URL: `https://zennzai2007.github.io/akatuki/`
   - Redirect URLs: `https://zennzai2007.github.io/akatuki/**` と `http://localhost:3000/**`
4. Project Settings の Project URL と anon（Publishable）key を `docs/config.js` に書く

### メール通知の準備（任意）

申し込みが届いたときに出品者へ、承認されたときに申込者へメールを送れます。使わない場合は設定不要です（サイトは通知なしで動きます）。

1. **Mailjet** に登録し、送信元にするメールアドレスを認証する（Account settings → Sender domains & addresses → Add a sender address）。同じ画面の API Key Management で、API キーとシークレットキーを控える。
2. Supabase の **Edge Functions** で `notify` という名前の関数を作り、`supabase/functions/notify/index.ts` の内容を貼ってデプロイする。
3. Edge Functions の **Secrets** に次を登録する。
   - `MAILJET_API_KEY`（Mailjet の API キー）
   - `MAILJET_SECRET_KEY`（Mailjet のシークレットキー）
   - `SENDER_EMAIL`（Mailjet で認証した送信元アドレス）
   - `SENDER_NAME`（差出人名。例: YUマーケット）
   - `SITE_URL`（`https://zennzai2007.github.io/akatuki/`）
   - `WEBHOOK_SECRET`（自分で決める合言葉）
4. **Database → Webhooks** で `applications` テーブルの Insert と Update に対する Webhook を作り、`notify` 関数を呼ぶようにする。HTTP ヘッダーに `x-webhook-secret` を追加し、3 で決めた合言葉を入れる。

送信元アドレスが個人のものになるため、受信側には差出人としてそのアドレスが見えます。大学のメールサーバーで迷惑メール扱いになることがあるので、最初は自分宛てで届き方を確認してください。

### ローカルで開く

```bash
node server.js
```

- このPC: <http://localhost:3000>
- スマホ: 起動時に表示される `http://<PCのIPアドレス>:3000`（同じWi-Fiに接続していること）

ローカルから新規登録した場合、確認メールのリンクは localhost に戻るので、PC で開いてください。

### 公開

`main` ブランチに push すると、GitHub Pages が `docs/` を公開します。

## 構成

```
docs/
  index.html   全画面のマークアップ
  style.css    スタイル
  app.js       画面遷移・認証・検索・出品・申込などの処理
  config.js    Supabase の接続先（anon key は公開前提の鍵）
supabase/
  schema.sql   テーブル・RLS・RPC・Storage の定義（SQL Editor で実行する）
server.js      動作確認用の簡易HTTPサーバー
```

外部ライブラリは CDN から読み込みます（supabase-js、HEIC の写真を読むときだけ heic2any）。

## 制限事項

- 登録できるのは `@yamaguchi-u.ac.jp` のメールアドレスだけです。
- **通知はありません。** 申込・承認・完了があっても、メールやプッシュ通知は届きません。相手の画面は再読み込みしたときに更新されます。
- **メールアドレスはほかの利用者に表示しません。** 相手への連絡は、取引中だけ使える「メッセージ」で行います。取引中でない人や第三者は読めません。
- **メールで知らせるのは、申し込みと承認のときだけです**（上の設定をした場合）。メッセージや受け渡し完了では送りません。
- **メッセージに通知はありません。** 画面を開いている間は10秒ごとに新着を取りに行きますが、閉じていると気づけません。
- **通報は記録されるだけです。** 通報がついても出品は自動では消えません。運営者が Supabase の Table Editor で `reports` を見て、必要なら手で対処します（通報の一覧を見られるのは運営者だけで、アプリからは誰も読めません）。通報が届いたことの通知もないので、ときどき確認してください。
- **同時に申し込めるのは3件までです**（申込中＋取引中の合計）。取引が完了・取消になれば、また申し込めます。
- **評価は出品者に対してだけ、取引が完了した相手からしか付きません。** 誰がどう評価したかは本人以外には見えず、画面に出るのは合計だけです。付けた評価は取り消せません。
- **禁止物は利用規約に一覧で書いてあります。** 出品フォームでも、当たらないことの確認にチェックが必要です。
- **問題のある利用者は止められます。** Supabase の Table Editor で `profiles` の `blocked` にチェックを入れると、その人は出品・申し込み・メッセージができなくなります（画面でもボタンが押せず、DB 側でも拒否します）。外すと元に戻ります。
- **通報された取引では、両者ともメッセージを送れなくなります。** 過去のやりとりは読めます。受け渡し完了・取り消しは「取引」画面から従来どおりできます。
- **通報には、そのときの出品内容とやりとりのコピーが残ります。** あとで出品が取り消されたり、取引が完了してメッセージが消えたりしても、通報から確認できます。この扱いは利用規約にも書いてあります。
- **端末にデータを保存しません。** 端末に残るのはログイン状態だけで、これは supabase-js が認証トークンを保存しているものです。
- 「欲しいです」（募集）、欲しいものリスト、ホームのおすすめ、出品の「色」は、画面を簡単にするため削除しました（git の履歴に残っています）。
- Supabase の無料プランは、1週間アクセスが無いとプロジェクトが一時停止します。
- Supabase 標準のメール送信は時間あたりの上限が小さく、確認メールが遅れることがあります。
